# Phase 4: Feature テストのファイル構成・命名は手順書が指定していない

- フェーズ: Phase 4
- 状態: 未分類
- 初回観測: 2026-08-16
- 実行モデル: claude-sonnet-5

## 何が起きたか

`scaffold-phase4-ui-tests.md` は「Feature テスト（`php artisan test`）でも主要フロー…を
押さえること」とテスト対象の観点は列挙するが、Feature テストファイルの置き場所・
分割単位・命名規則については何も定めていない。Phase 1〜3 の手順書にも Feature テストの
ディレクトリ構成に関する記述は見当たらなかった。

今回は次のように自分で決めた:

- `tests/Feature/` 配下をリソース単位のサブディレクトリ（`Books/`, `Lendings/`, `Admin/`）に
  分割し、1 操作 1 ファイル程度の粒度で作成（`RequestLendingTest.php`,
  `ApproveLendingTest.php`, `BookCrudTest.php` 等）
- ページネーション検証は完了基準が明示するメンバー蔵書一覧（Livewire::test 形）と、
  手順書が (b) パターンの例に挙げる管理蔵書一覧の 2 箇所のみで行い、他の一覧
  （カテゴリ・タグ・ユーザー・監査ログ）には個別のページネーションテストを書かなかった
  （完了基準の文言はメンバー蔵書一覧のみを明示的に要求している）
- 「role のマスアサインメント防止」の検証を、HTTP 経由の再現ではなく
  `User::getFillable()` に `role` が含まれないことを確認する形の軽量なテストにした
  （`docs/api-spec.md` の該当注記はコントローラの実装方針であり、直接のエンドポイントは
  ロールを明示代入するため HTTP 経由では黙って無視される動きを再現しづらい）

モデル限界のいずれに当たるかの切り分けを行っていない（Sonnet モードでは非実施）。
