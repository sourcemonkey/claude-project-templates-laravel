# Phase 1 トライアルで権限拒否されたコマンド（git のグローバル設定オプション付き呼び出し）

- フェーズ: Phase 1
- 状態: 未解決
- 初回観測: 2026-07-22

## 何が起きたか

セッション冒頭の作業ツリー状態確認で、日本語ファイル名をそのまま表示させるために
`git -c core.quotepath=false status --short` を実行したところ、許可リストに一致せず
承認を求められて拒否された（ヘッドレスのため応答できず失敗）。オプションを外した
`git status --short` に切り替えたところ通った。

Phase 1 の他のコマンドはすべて許可リストで通っており、拒否はこの 1 件のみ。

## 根拠

拒否されたコマンド（原文）:

```
git -c core.quotepath=false status --short
```

- ツールからの応答: `This command requires approval`
- 直後に切り替えた代替（成功）: `git status --short`

許可リストには `Bash(git status *)` 系の前置パターンはあると見られるが、
`git -c <key>=<value> status ...` は先頭が `git -c` になるため前置パターンに
一致しない（前提条件 5 が挙げる `git -C <path>` と同種の「git のサブコマンド前に
別トークンが挟まる」ケース）。

## なぜ自動で直さなかったか

「共通の進め方」手順 4 のうち「許可リストの不足」に該当。反映先の
`.claude/settings.json` はヘッドレスから書き込めず、`patches/` 経由でしか
恒久化できないため。

## 選択肢

1. **何もしない（運用で回避）** — `git status` はオプションなしで使えば通る。
   日本語ファイル名は `-c core.quotepath=false` が無くても、実用上は
   コミット対象の把握に支障がない（`git status --short` でパスは表示される）。
   影響: 追加設定なし / 懸念: 別の Claude が同じ `-c` 付き呼び出しをして再度躓く。
2. **`Bash(git -c core.quotepath=false status:*)` を許可リストに追加** — 特定の
   グローバル設定オプション付き呼び出しだけを通す。影響: 最小の追加 /
   懸念: `-c` に渡せるキーは任意なので、`core.quotepath` 以外を使いたくなると
   再度追加が要る。
3. **前提条件 5 に「git はサブコマンドの前にトークンを挟まない形で呼ぶ
   （`-c`/`-C` は使わない）」旨を明記** — 設定は変えず、手順側で回避を徹底させる。
   影響: ルート `.claude/settings.json` を触らずに済む / 懸念: 恒久的な制約の明文化に
   とどまり、利便性は上がらない。

## 推奨

案 3 + 案 1。今回の用途（日本語ファイル名の表示）は `-c core.quotepath=false` が
無くても代替できており、許可リストを広げる実益が小さい。前提条件 5 は既に
`git -C <path>` の禁止を挙げているので、そこへ `git -c <key>=<value>` も同様に
避ける旨を 1 行足すのが影響範囲最小。

## 決めてほしいこと

`git -c ... status` を許可リストに追加するか（案 2）、それとも前提条件 5 に
「git はサブコマンド前にトークンを挟まない」旨を明記して運用回避に寄せるか（案 3）。

## 暫定対応

`git status --short`（オプションなし）に切り替えて続行した。テンプレート本体への
差分は入れていない。
