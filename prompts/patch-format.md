# 修正パッチの書式

`prompts/trial-phase.md` の補足。**`.claude/` 配下のファイルを直す必要が出たときだけ
Read すれば足りる**（ヘッドレスはこの配下へ書き込めないため、変更点だけを
`patches/edit-*.md` に置いて対話セッションの適用を待つ）。

ヘッドレスから書き換えられない `.claude/` 配下のファイルへの修正は、**変更点だけ**を
`patches/edit-*.md` に置き、対話セッションが適用する。

### ファイル

- **1 対象ファイルにつき 1 パッチファイル**。`patches/edit-<元のファイル名>.md`
  （例: `patches/edit-scaffold-phase1-skeleton.md`）
- `patches/` 直下の接頭辞は 2 種類だけ。`edit-` = 適用待ちの修正、`issue-` = 判断待ちの申し送り
- **`patches/` はリポジトリルート直下**。手順 2 で `my-laravel-app/` へ移動した後に
  相対パスで書くと `my-laravel-app/patches/` に誤配置される

### 書式

**外側のフェンスは 4 連バッククォート（` ```` `）を使う。** 手順書はコードフェンスを
多数含むため（Phase 1 で 22 箇所、Phase 3 で 18 箇所）、3 連で囲むと最初の内側フェンスで
閉じてしまい、以降が壊れる。内側に 4 連以上が現れる場合はさらに増やす。

`````markdown
# scaffold-phase1-skeleton.md への修正

- 対象: `my-laravel-app/.claude/commands/scaffold-phase1-skeleton.md`
- 基準コミット: 848d822
- 操作数: 2

## 1. 変更 — Composer のバージョン確認が抜けていた

### before

````
（原文をそのまま。ファイル内で一意になる長さまで含める）
````

### after

````
（置換後）
````

## 2. 追加 — ポート競合時の対処が書かれていなかった

### before

````
（挿入位置の直前にある既存の記述）
````

### after

````
（同じ記述 + 追加したい内容）
````
`````

**`基準コミット` は必ず書く**（`git log -1 --format=%h` で取る）。適用側が
`git diff <基準コミット> -- <対象>` を打てば、その間に対象ファイルが動いたかどうかが
分かる。フル版の上書きと違い、**他の変更を黙って潰す事故が起きない**。

### 操作の種類

見出しに `## <番号>. <操作> — <一行の説明>` の形で操作名を書く。

| 操作 | before | after |
|---|---|---|
| **変更** | 元の記述 | 新しい記述 |
| **追加** | 挿入位置の直前（または直後）にある既存の記述 | それ + 追加内容 |
| **削除** | 削除対象 + 前後のアンカー行 | **アンカー行のみ** |
| **全置換** | 対象文字列 | 置換後（同じ文字列が複数あり全部直す場合） |
| **新規作成** | （なし） | ファイルの全文 |
| **ファイル削除** | （なし） | （なし。パスだけ書く） |
| **全文置換** | （なし） | ファイルの全文 |

**削除で `after` を空にしない。** 空文字なのか空行なのかが曖昧になり、前後の改行の
扱いで壊れる。前後 1 行をアンカーとして両方に含め、`after` を非空にする。

**変更量が元ファイルの概ね半分を超える場合は「全文置換」を選ぶ**。差分にする利点が
消えるうえ、操作数が増えて適用の失敗確率が上がるため。ここは判断せず量で決める。

### 規則

1. **`before` はファイル内で一意になるまで前後を含める。** 一意にできない場合は
   操作を分割するか「全置換」を使う（Edit ツールと同じ制約）
2. **同一ファイルへの複数操作は記載順に適用する。** 2 番目以降の `before` は、
   それ以前の操作を適用した後の状態に一致させる
3. **`before` は原文のまま写す。** 要約・整形・空白の詰め直しをしない。1 文字でも
   違えば適用に失敗する

### 適用（対話セッション側の手順）

1. `git diff <基準コミット> -- <対象>` で、対象ファイルが動いていないか確認する
2. 記載順に Edit ツールで適用する
3. **`git diff` で結果を確認してからコミットする**。フル版が持っていた
   「見たものがそのまま入る」性質が差分方式では失われるため、ここで補う
4. 適用済みのパッチファイルを削除し、修正と同じコミットに含める
