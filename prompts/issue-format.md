# 申し送りの書式

`prompts/trial-phase.md` の補足。**`patches/issue-*.md` を書く必要が出たときだけ
Read すれば足りる**（ヘッドレスでは決められない事項を、次のセッションのユーザーと
Claude Code が対話で解決できる形にして残すためのファイル）。

置き場所と 1 件 1 ファイルの規則は `prompts/trial-phase.md` の
「判断が必要な事項の申し送り」節にある。ここでは中身の書式だけを定める。

`状態:` は `未解決`（判断待ち）か `未分類`（`--model sonnet` の観測記録。切り分けから行う）。
`実行モデル:` は観測したセッションのモデル名で、**再現性の判断に要る**ため必ず書く。

```markdown
# <一行で問題を言い切るタイトル>

- フェーズ: Phase 3
- 状態: 未解決
- 初回観測: 2026-07-19
- 実行モデル: claude-opus-5

## 何が起きたか

手順書のどのステップで、何をしたら、何が起きたか。

## 根拠

エラー出力・コマンド・ファイルの該当箇所を**原文のまま**引く。
要約・言い換えをしない（別セッションが再現を試みる一次情報になるため）。

（エラー出力の原文をコードブロックで）

- 関連ファイル: `my-laravel-app/.claude/commands/scaffold-phase3-ui.md:120`

## なぜ自動で直さなかったか

「共通の進め方」手順 4 の振り分け基準のどれに当たるかを 1 行で。

## 選択肢

1. **<案 A>** — 影響: … / 懸念: …
2. **<案 B>** — 影響: … / 懸念: …

## 推奨

案 A。理由を 1〜2 行。

## 決めてほしいこと

<ユーザーが Yes/No か択一で答えられる 1 つの問い>

## 暫定対応

トライアルを先に進めるために取った回避策があれば書く。無ければ「なし」。
**回避策をテンプレート本体に入れた場合は、その差分もここに明記する**
（決着後に取り消す必要があるため）。
```
